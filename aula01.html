Fundamentos da Teoria dos Conjuntos

Conceitos básicos e operações fundamentais

O que é um Conjunto?

collection

Definição

Um conjunto é uma coleção bem definida de objetos, chamados elementos. Exemplos práticos no contexto ENADE.

Conjunto A

Linguagens do Aluno

A = {Python, Java, C++}

Python ∈ A (pertence)

Conjunto B

Vagas do Mercado

B = {Java, JavaScript, TypeScript}

Rust ∉ B (não pertence)

Conjunto Vazio

Linguagens Obsoletas

C = ∅ (vazio - sem elementos)

Símbolo: ∅ ou { }

Subconjunto

Frontend Languages

D ⊆ B (D é subconjunto de B)

Todos elementos de D em B

Representação de Conjuntos

A
B
A ∩ B

Diagrama de Venn

Pertinência

∈ pertence   ∉ não pertence

Java ∈ A, Rust ∉ A

Subconjunto

⊆ contido   ⊄ não contido

{Java} ⊆ A

Conjunto Vazio

∅ ou { } = sem elementos

Linguagens inúteis = ∅

Cardinalidade

|A| = total de elementos

A = {Python, Java, C++} → |A| = 3

União (A ∪ B)

Definição

A ∪ B contém TODOS os elementos que estão EM A OU EM B (ou em ambos)

Se A = {1,2,3}, B = {3,4,5}, então A ∪ B = {1,2,3,4,5}

Exemplo Prático

Você conhece: {Python, Java}

Seu colega conhece: {Java, JavaScript}

Linguagens conhecidas = {Python, Java, JavaScript}

Todos os idiomas que VOCÊ OU seu colega falam

Interseção (A ∩ B)

Definição

A ∩ B contém APENAS os elementos que estão EM A E EM B (em ambos)

Se A = {1,2,3}, B = {3,4,5}, então A ∩ B = {3}

Exemplo Prático

Candidato sabe: {Python, Java, JavaScript}

Vaga requer: {Java, JavaScript, C#}

Compatível = {Java, JavaScript}

Skills que o candidato E a vaga têm em COMUM

Diferença (A − B)

Definição

A − B contém elementos que estão EM A MAS NÃO em B

Se A = {1,2,3}, B = {3,4,5}, então A − B = {1,2}

Exemplo Prático

Clientes site: {100 clientes}

Clientes app: {60 clientes}

Clientes APENAS site = {40 clientes}

Clientes que compraram no site MAS NÃO no app

Complemento (Aᶜ)

Definição

Aᶜ contém TODOS os elementos do universo U que NÃO estão em A

Se U = {1,2,3,4,5} e A = {1,2,3}, então Aᶜ = {4,5}

Exemplo Prático

Alunos = 30 pessoas

Passaram = 25 pessoas

Reprovados = 5 pessoas

Alunos que NÃO passaram na prova

Resumo Visual das Operações

∪ União

TODOS os elementos em A OU B

A ∪ B = elementos em A ou B ou ambos

∩ Interseção

APENAS elementos comuns

A ∩ B = elementos em A E B

− Diferença

EM A MAS NÃO em B

A − B = elementos só em A

ᶜ Complemento

NÃO em A

Aᶜ = tudo que não é A

Como Funciona a Múltipla Escolha?

Estrutura da Questão

1 enunciado + 5 alternativas (A, B, C, D, E)

Apenas 1 alternativa correta

Requer reconhecer a resposta correta

Estratégia 1

Elimine alternativas obviamente erradas

Trabalhe com as que restam

Aumenta probabilidade de acerto

Estratégia 2

Procure por excessos (nunca, sempre, todos)

Geralmente são incorretos

Conjuntos raramente "nunca" ou "sempre"

Estratégia 3

Leia cada alternativa como verdadeira

Descubra qual é logicamente válida

Verifique contra o enunciado
QUESTÃO EXPLICADA

Múltipla Escolha - Exemplo 1

Uma streaming tem 200 usuários. 120 ouvem Pop, 80 ouvem Rock. 30 ouvem ambos. Quantos ouvem APENAS um dos dois gêneros?

Dissecando a Questão

Dados do Problema

Pop: 120 usuários

Rock: 80 usuários

Ambos: 30 usuários

O que Pergunta?

"APENAS um dos dois" significa

(Pop − Rock) ∪ (Rock − Pop)

Cálculo Pop Apenas

Pop − Ambos = 120 − 30 = 90

Pessoas que ouvem POP mas não Rock

Cálculo Rock Apenas

Rock − Ambos = 80 − 30 = 50

Pessoas que ouvem ROCK mas não Pop

Total Apenas Um

90 + 50 = 140 usuários

Ouvem apenas Pop ou apenas Rock

Resposta: C

140 usuários ouvem APENAS um dos dois gêneros

Eliminamos o overlap de 30

Conjuntos e SQL: A Conexão

Operação de Conjuntos

∪ União

Combina TODOS os elementos de A e B

∩ Interseção

Apenas elementos COMUNS a A e B

A − B Diferença

Elementos em A que NÃO estão em B

A ∪ B Completa

Tudo de A e tudo de B (sem repetir)

⟷ ⟷ ⟷ ⟷
Comando SQL

UNION

Combina resultados de dois SELECTs

INNER JOIN

Retorna apenas registros em ambas tabelas

EXCEPT / MINUS

Registros em A que não existem em B

FULL OUTER JOIN

Todos os registros de ambas tabelas

INNER JOIN = Interseção (A ∩ B)

Customers
Orders

Retorna: A ∩ B

Apenas registros em AMBAS

SQL intersection.sql 
SELECT c.id, c.name, o.order_id
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id

-- Retorna APENAS clientes que fizeram pedidos
-- Interseção: Clientes ∩ Compradores
link

Lógica: Registros com correspondência em ambas as tabelas. Clientes sem pedidos são excluídos.

LEFT JOIN = Conjunto A Completo

TODOS
Orders

Retorna: A completo

+ match de B se houver

SQL left_join.sql 
SELECT c.id, c.name, o.order_id
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id

-- Retorna TODOS os clientes (A)
-- order_id = NULL se sem pedidos
link

Lógica: Preservar todos da tabela esquerda. Sem match → campos da direita ficam NULL.

FULL OUTER JOIN = União (A ∪ B)

TODOS
TODOS

Retorna: A ∪ B

Tudo de ambas as tabelas

SQL full_outer_join.sql 
SELECT c.id, c.name, o.order_id
FROM customers c
FULL OUTER JOIN orders o ON c.id = o.customer_id

-- Retorna TUDO: Clientes + Pedidos
-- NULL onde sem correspondência
link

Lógica: Combina tudo de ambas as tabelas. Sem match → NULL nos campos da outra.

EXCEPT/MINUS = Diferença (A − B)

SÓ A
excluído

Retorna: A − B

Elementos só em A

SQL difference.sql 
SELECT customer_id FROM orders
WHERE order_date IN (
    SELECT id FROM customers
    EXCEPT
    SELECT customer_id FROM returns
)
-- Clientes que compraram MAS NÃO devolveram
link

Lógica: Elementos na primeira query que NÃO aparecem na segunda.

PARTE 4

Questões ENADE: Asserção-Razão

Formato e estratégias de resolução

Como Funciona Asserção-Razão?

help

Estrutura

Asserção I: Uma afirmação sobre um conceito. PORQUE Asserção II: Uma justificativa ou explicação. Você deve avaliar se ambas são verdadeiras E se II justifica I.

Alternativa A

I e II verdadeiras, e II JUSTIFICA I

Melhor resposta possível

Alternativa B

I e II verdadeiras, mas II NÃO justifica I

Ambas corretas, mas desconexas

Alternativa C

I verdadeira, II falsa

Apenas uma está certa

Alternativa D

I falsa, II verdadeira

Lógica invertida
QUESTÃO EXPLICADA

Asserção-Razão - Exemplo

Enunciado

I. A operação INNER JOIN retorna apenas registros presentes em ambas as tabelas, representando a interseção de conjuntos.

PORQUE

II. O INNER JOIN implementa o conceito matemático de interseção (∩) ao combinar dados de duas tabelas baseado em uma condição de igualdade.

Avalie as alternativas:

A) As asserções I e II são verdadeiras, e a II é justificativa correta da I.

B) As asserções I e II são verdadeiras, mas a II não é justificativa correta da I.

C) A asserção I é verdadeira, e a II é falsa.

D) A asserção I é falsa, e a II é verdadeira.

E) As asserções I e II são falsas.

Dissecando a Questão

Analisando I

INNER JOIN retorna apenas registros em ambas?

✓ VERDADEIRO

Analisando II

É baseado em interseção (∩)?

✓ VERDADEIRO

II Justifica I?

A razão explica a asserção?

✓ SIM - II explica por que I funciona

Resposta: A

Ambas verdadeiras E II justifica I

Conexão lógica perfeita

Fluxo de Decisão - Asserção-Razão

1. A Asserção I é VERDADEIRA?

Não? → Vá para passo 3

Sim? → Continue no passo 2

2. A Asserção II é VERDADEIRA?

Não? → Resposta é C (I verdadeira, II falsa)

Sim? → II JUSTIFICA I? Se sim = A, Se não = B

3. A Asserção II é VERDADEIRA?

Não? → Resposta é E (Ambas falsas)

Sim? → Resposta é D (I falsa, II verdadeira)

Caso Real: Segmentação de Clientes

O Problema

Varejista com 10.000 clientes quer segmentar para campanhas de marketing personalizadas

Dados

Clientes Online: 7.000

Clientes Loja: 5.000

Ambos: 2.000

Análise com Conjuntos

Omnichannel: Online ∩ Loja = 2.000 (compradores em ambos)

Apenas Online: Online − Loja = 5.000

Apenas Loja: Loja − Online = 3.000

Resultado

Omnichannel recebe 15% desconto (melhor retenção)

Cada grupo diferente tratamento marketing

Impacto: +25% em repea rate

Caso Real: Análise de Churn

O Problema

SaaS com 5.000 clientes ativos. Número caindo mês a mês

Dados Mês Anterior

Clientes Ativos: 5.000

Clientes Este Mês: 4.850

Cálculo de Churn

Churn = Mês Anterior − Mês Atual

Churn = 5.000 − 4.850 = 150

Taxa de Churn: 3% ao mês

Ação

Analisar os 150 clientes que saíram

Identificar padrões de risco

Implementar retenção preventiva

Como Funciona Complementação Múltipla?

Estrutura

Enunciado com 4 proposições (I, II, III, IV)

Você marca QUAIS são verdadeiras

Alternativas

A) Apenas I e II

B) Apenas II e III

C) Apenas I, III e IV

Estratégia 1

Analise cada proposição ISOLADAMENTE

Verdadeira ou Falsa? Marque

Estratégia 2

Depois combine suas marcações

Procure a combinação correta

QUESTÃO EXPLICADA

Complementação Múltipla - Exemplo

Sobre Operações de Conjuntos e Dados

I. A união de dois conjuntos sempre contém mais elementos que ambos separadamente.

II. A interseção de dois conjuntos contém APENAS os elementos comuns a ambos.

III. O complemento de um conjunto A depende da definição do conjunto universo U.

IV. A diferença A − B sempre contém pelo menos um elemento se A ≠ B.

Resposta: II e III são verdadeiras

Proposição I

Se A={1,2,3}, B={2,3,4} → A∪B={1,2,3,4}

Mas se B⊆A, |A∪B|=|A|

✗ FALSA

Proposição II

A∩B retorna apenas elementos presentes em ambos os conjuntos

✓ VERDADEIRA

Proposição III

Aᶜ só faz sentido com U definido. Complemento é relativo ao universo

✓ VERDADEIRA

Proposição IV

Se A={1,2,3}, B={1,2,3} → A−B=∅

✗ FALSA

Estratégia de Resolução Passo a Passo

Passo 1: Leia o Enunciado

Entenda o contexto. O que está sendo testado?

Passo 2: Analise I

Verdadeira ou Falsa? Justifique sua resposta com exemplos.

Passo 3: Analise II, III e IV

Faça o mesmo. Marque V ou F para cada uma.

Passo 4: Combine Resultados

Se I=V, II=V, III=F, IV=F, procure por "I e II"

Passo 5: Revise Dupla Conferência

Verifique as falsas uma segunda vez antes de confirmar

Complementação Múltipla - Segunda Prática

Sobre Propriedades de Conjuntos

I. Se |A ∪ B| = |A| + |B|, então A e B são disjuntos (sem elementos comuns).

II. O complemento de um conjunto é único e bem definido independentemente do universo.

III. De Morgan: (A ∪ B)ᶜ = Aᶜ ∩ Bᶜ é uma propriedade fundamental de conjuntos.

IV. A cardinalidade de A ∩ B nunca pode ser maior que a cardinalidade de A ∪ B.

Resposta: I, III e IV são verdadeiras

Proposição I

Se não há overlap, a soma funciona. Disjuntos = sem ∩

✓ VERDADEIRA

Proposição II

Complemento DEPENDE de U definido. Sem U, não existe Aᶜ

✗ FALSA

Proposição III

Lei de De Morgan é propriedade fundamental da álgebra de conjuntos

✓ VERDADEIRA

Proposição IV

A∩B ⊆ A∪B sempre. Logo |A∩B| ≤ |A∪B|

✓ VERDADEIRA
